## 1. 一行原理

在伤害链的**最后一级** `ApplyGeneralDamageModifiers` 里，对「攻击方是马」的伤害乘一个倍率：

- 判定：`AttackInformation.IsAttackerAgentMount`（冲撞时攻击者就是马）；
- 倍率：按骑手是否真人取 `PlayerMultiplier` / `BotMultiplier`；
- 限流：每秒最多放大 `MaxEmpoweredHitsPerSecond` 次，超出的按原版结算。

为什么不改 `mpitems.xml` 的 `charge_damage`：那样要逐匹马改、新增马匹要补、Steam 更新会覆盖，且无法只放大玩家。

## 2. 伤害管线与调用链

### 2.1 调用链（IL 验证）

```
Mission.ChargeDamageCallback(...)
  -> Mission.GetAttackCollisionResults
     -> AttackInformation..ctor(attacker = 马)     // IsAttackerAgentMount = attacker.IsMount = true
     -> AgentApplyDamageModel.CalculateDamage       // 非虚，内部按顺序调用下面几个虚方法
          IsDamageIgnored
          ApplyDamageAmplifications
          ApplyDamageScaling
          ApplyDamageReductions
          ApplyGeneralDamageModifiers              // ← 本模组重写这里，×倍率
     -> Round -> collisionData.InflictedDamage
```

被动攻击（马撞人）的**基础威力**另走 `CalculatePassiveAttackDamage(in AttackInformation, in AttackCollisionData, float baseMagnitude)`，但那一环只是基础值，不是最终伤害（见第 3 节第 2 条）。

### 2.2 关键类型与判定

| 项 | 结论 |
|---|---|
| 基类链 | `MultiplayerAgentApplyDamageModel` → `AgentApplyDamageModel`（abstract）→ `MBGameModel<AgentApplyDamageModel>`；public、非 sealed |
| 本模组重写 | `ApplyGeneralDamageModifiers(in AttackInformation, in AttackCollisionData, float)` |
| 冲撞判定 | 主判 `IsAttackerAgentMount`；次判 `IsAttackerAgentDoingPassiveAttack && DoesAttackerHaveMountAgent` |
| 真人判定 | 取马的 `RiderAgent`：`MissionPeer != null` / `IsPlayerControlled` / `!IsAIControlled` 任一成立即真人；取不到骑手退回 `OwningAgentMissionPeer` / `IsAttackerPlayer` |
| 目标保护 | `IsVictimAgentNull` 或 `!VictimAgent.IsActive()` 时跳过 |
| 冲撞基础值 | `mpitems.xml` 每匹马的 `charge_damage` → `AgentDrivenProperties.MountChargeDamage` |
| 算不算冲撞 | `monsters.xml` 的 `relative_speed_limit_for_charge`（马 5.0 / 人 4.3） |
| 服务器选项 | 无冲撞倍率选项（已枚举全部 51 个 `OptionType`） |

## 3. 三个踩过的坑

| # | 现象 | 原因 | 落地做法 |
|---|---|---|---|
| 1 | 重写 `CalculateDamage` 编译报 **CS0506** | 它不是 `virtual`，只是顺序调用各 `Apply*` | 只能重写它调用的虚方法 |
| 2 | 重写 `CalculatePassiveAttackDamage` 没效果、有时算出 0 | 它只是被动分支的**基础威力**（原版实现仅 `ldarg.3; ret`），冲撞时该分支可能给 0 | 改在 `ApplyGeneralDamageModifiers`（最后一环）乘算，乘的才是最终伤害 |
| 3 | 直接给 `MissionGameModels.Current.AgentApplyDamageModel` 赋值编译报 **CS0200** | setter 是 private | 用 `IGameStarter.AddModel()` 注册（见第 4 节），再用反射写后备字段兜底 |

另外：`MBSubModuleBase.OnSubModuleLoad` 在本版本是 `protected internal`，不能当公共钩子重写，所以配置改成**懒加载**（首次使用时读）。

## 4. 注册与生效时序

```
游戏启动
  → 模块 InitializeGameStarter(game, gameStarter)
       ChargeConfig.EnsureLoaded()            // 首次读配置
       gameStarter.AddModel(new ChargeDamageModel())
  → MissionGameModels 构造时
       GetGameModel<AgentApplyDamageModel>()  // 从模型列表【尾部】往前找，最后加入的优先生效
  → 每张图 OnMissionBehaviorInitialize(mission)   // 仅 GameNetwork.IsServer
       若当前模型不是 ChargeDamageModel，用反射写 <AgentApplyDamageModel>k__BackingField 兜底
```

- 兜底路径会打印 `[ChargeTweaks] OnMissionBehaviorInitialize: 已强制替换伤害模型 | ...`；
- `OnMultiplayerGameStart` 也会做一次同样的兜底检查；
- 两种路径都是**赋值替换**，不会叠加。

源码分工：

| 文件 | 职责 |
|---|---|
| [`../src/ChargeConfig.cs`](../src/ChargeConfig.cs) | 读 XML、校验与回退默认值、静态缓存、路径解析 |
| [`../src/ChargeDamageModel.cs`](../src/ChargeDamageModel.cs) | 伤害模型：冲撞判定、真人/AI 取倍率、每秒限流、NaN 与已死目标保护 |
| [`../src/ChargeTweaksSubModule.cs`](../src/ChargeTweaksSubModule.cs) | 模块入口：`InitializeGameStarter` 注册 + 每图反射兜底 |

## 5. 配置的运行时行为

- **读取时机**：进程内**第一次使用时读一次**（`EnsureLoaded` 静态缓存），之后不再重读。
  → **改 `charge_config.xml` 必须重启服务器**，换图不会重新加载（不要按「换图生效」操作）。
- **路径**：优先 `ModuleHelper.GetModuleFullPath("ChargeTweaks")`；失败时按 DLL 相对路径推导（该兜底有已知瑕疵，见第 8 节），两条路都不通就打印 `找不到模块目录` / `配置不存在` 并全程走默认值。
- **解析规则**：任何键缺失、解析失败或越界，都回退到默认值，绝不抛异常打断服务器启动。

| 键 | 合法范围 | 非法/缺失时 |
|---|---|---|
| `PlayerMultiplier` | `> 0` 且 `<= 1000` | 回退 **20** |
| `BotMultiplier` | 同上 | 回退 **1.0** |
| `AffectFriendlyFire` | `true` / `false` | 非 `true` 即 **false** |
| `MaxEmpoweredHitsPerSecond` | `0 ~ 1000` | 回退 **8**（0 = 不限制） |
| `MaxDamage` | `> 0` 且 `<= 1000000` | 回退 **0**（不限制） |
| `LogDamage` | `true` / `false` | 非 `true` 即 **false** |
| `Multiplier`（旧键） | `> 0` 且 `<= 1000` | 作为 `PlayerMultiplier` / `BotMultiplier` 缺失或非法时的回退值（两者共用该倍率） |

启动与调试日志：

```
[ChargeTweaks] 配置: 玩家倍率=20 AI倍率=1 友伤放大=False 每秒上限=8 伤害上限=0 日志=False | <配置路径>
[ChargeTweaks] 已注册 ChargeDamageModel | 玩家倍率=20 AI倍率=1
[ChargeTweaks] 冲撞伤害 12.0 -> 240.0 (x20, 玩家骑手) | 受害者=xxx
[ChargeTweaks] 冲撞被限流（超过每秒 8 次），按原版伤害结算 | 受害者=xxx
```

## 6. 构建

在 mod 根目录（`../`）下执行 `build.ps1`：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -ServerBin "C:\DedicatedServer\bin\Win64_Shipping_Server"
```

脚本做的事：

1. 在 `dotnet\sdk\<最新版本>\Roslyn\bincore\csc.dll` 找到 Roslyn；
2. 在 `dotnet\shared\Microsoft.NETCore.App\8.0.*` 找最新的 .NET 8 运行时，作为引用程序集；
3. 引用运行时里的 `System.*.dll` + 服务器目录下的 `TaleWorlds*.dll`；
4. `-nostdlib` 编译 `../src/*.cs` → `../ChargeTweaks/bin/Win64_Shipping_Server/ChargeTweaks.dll`。

参数：`-ServerBin`（默认取本目录**上一级**的 `bin\Win64_Shipping_Server`，仓库单独存放时一般要显式指定）、`-DotnetRoot`（默认 `C:\Program Files\dotnet`）、`-DotnetRuntimeVersion`（默认自动选最新的 8.0.x）。

三个坑：

- 只装了 net10 targeting pack、没有 net8 ref pack 时，`dotnet build -f net8.0` 会因缺目标包失败，所以直接调 `csc`；
- `-nostdlib` 时必须排除 `*Native.dll`、`coreclr.dll`、`clrjit.dll` 等原生文件，否则报 `CS0009`；
- `build.ps1` 本身保持**纯 ASCII**：Windows PowerShell 5.1 会按 ANSI 读文件，中文注释会导致语法错误。

| 版本 | 内容 |
|---|---|
| v1.0.0 | 单倍率 `Multiplier`，所有冲撞一视同仁；线上 13 bot 对局约 5 分钟客户端崩溃 |

崩溃的取证、根因与修复过程独立成文：[客户端崩溃排查记录](./客户端崩溃排查记录.md)。

当前产物：`ChargeTweaks.dll` 12,288 字节（v1.1.0）。改代码后建议至少自查：

1. 骑马撞人出现放大日志，近战/远程没有；
2. `BotMultiplier=1.0` 时 AI 骑兵互撞**不**放大；
3. 一次冲锋连撞多人能触发限流日志；
4. 改完配置重启后生效；同一进程内换图不会重读（预期行为）。

## 8. 已知限制与后续方向

- 只改冲撞这一段伤害，不改马匹速度/操纵、击退与落马规则；
- 与其它替换 `AgentApplyDamageModel` 的模组**互斥**（同一时间只有一个生效）；
- 配置不支持热重载，改动必须重启（要做的话可监听文件变更并在下一张图前重读）；
- 配置路径兜底有瑕疵：`ModuleHelper` 正常时无影响；一旦走 DLL 相对路径推导，`..\..\..` 多上溯了一层（落到 `Modules\` 而不是模块目录），结果等于找不到配置、回退默认值。

可扩展方向：

1. 按马种配倍率（读 `AttackerAgentCharacter` 对应的马匹物品）；
2. 结合 `AttackerAgentMovementVelocity` 做高速撞击额外加成；
3. 覆写 `DecideAgentKnockedDownByBlow` / `DecideMountRearedByBlow` 调整落马与击退；
4. 把倍率暴露到 `DedicatedCustomServerHelper` 网页面板（取决于其 API）。
